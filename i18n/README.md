# i18n catalogues

Project Fluent (`.ftl`) catalogues for the site, the docs, the Studio and the engine. English is the source and the fallback.
Design: kshana-pro `docs/design/i18n-0.40-design.md` (v2).

```
i18n/en/ui.ftl         site chrome, notices, switcher, Studio shell      (by hand)  ids site-*, notice-*, studio-*
i18n/en/glossary.ftl   terms: -tier-*, -verdict-*, -status-*, -term-*, -cmd-*, -unit-*, -advisory, -mt-notice   (by hand)
i18n/en/engine.ftl     text the engine writes for people                  ids engine-*
i18n/en/pages/*.ftl    one built page per file, generated by `extract`    ids seg-<sha12>
i18n/en/studio-js.ftl  the Studio's script-written text, from t() calls       ids js-*          (generated: `jsx`)
i18n/en/site-js.ftl    the site's script-written text, from t() calls         ids js-site-*     (generated: `jsx`)
i18n/en/studio-pages.ftl  Studio page text that carries inline markup         ids seg-<sha12>   (generated: `studio-pages`)
i18n/en/data.ftl       the prose of the JSON files the pages and Studio show  ids dat-<sha12>   (generated: `data`, spec: i18n/data-spec.json)
i18n/<lang>/...        the same file names, translated
```

## For translators

1. Copy the English file to `i18n/<lang>/` under the same name and translate the values. Keep every id, every
   `{ $variable }`, `{ -term }`, string-literal placeable (`{ "1,408" }`) and numbered tag (`<a1>..</a1>`, `<b>`, `<em>`,
   `<s1>`, `<c1/>`, `<br/>`). A `<cN/>` is a code span or a symbol kept verbatim; its text is in the comment above the message.
2. Numbers and versions are string-literal placeables so they cannot change; the build formats them for the locale.
3. A message with a count takes a selector for the plural categories of the language.
4. Never translate code, file names, commands, scenario and kind ids, or the tier and verdict words (see the glossary).

## The translators' loop (pages)

```
node tools/i18n.mjs status <lang>                    what is translated, missing, orphaned (per language; --json for pages)
node tools/i18n.mjs todo <lang> --out WORK           the English messages still missing, in chunks of about 26 KB (WORK/001.ftl ...)
                  [--page docs--agents]              only the pages whose file name starts with this
# translate the values in a chunk file, keeping every id, { $variable }, { "literal" }, <tag> and { -term }
node tools/i18n.mjs merge <lang> WORK/001.ftl ...    checks each message against the English one (variables, literals, tags, digits,
                                                     tier and verdict terms) and writes it into every page file that holds its id;
                                                     a message that fails is reported and not written
node tools/i18n.mjs check <lang>                     the whole catalogue of the language (syntax, plural categories, glossary tokens)
```

The whole-file catalogues (`ui`, `glossary`, `studio-js`, `site-js`, `studio-pages`, `data`) use the same loop with `--file`:
`node tools/i18n.mjs todo <lang> --file studio-js.ftl --out WORK`, translate the chunks, then
`node tools/i18n.mjs merge <lang> WORK/*.ftl --file studio-js.ftl`. `engine.ftl` is the engine's own (W55).
`node tools/i18n.mjs status` lists the coverage of every catalogue per language. After the English moves (an id changed),
`node tools/i18n.mjs migrate <lang> --from-rev <the revision your ids came from>` carries the translations to the new ids.
The engine version in running text is the variable `{ $version }`: keep it where it is. A number, a version or a symbol in a
`{ "..." }` literal is kept exactly; the build writes it in the language's own separators.

## Tools

`extract` regenerates `i18n/en/pages/` from the built English pages (pages that no longer exist are removed; `--version` or the root
`Cargo.toml` names the version that becomes `{ $version }`). An unchanged English segment keeps its id; a changed one gets a new id.
Segments on 25 or more pages are written once to `pages/_shared.ftl`. `pages/_index.json` lists each page's segment ids.

`images`, `apply`, `verify`, `english`, `sitemaps`, `langs`, `size`, `pseudo` and `csslint` are the build side (see `.github/workflows/i18n.yml`
and the translation step of `pages.yml`); `tools/i18n-fonts.py` makes the CJK subsets. Tests: `tools/i18n-negotiation-test.mjs`
(first-visit language, stored choice) and `tools/i18n-pseudo-test.mjs` (hard-coded text and overflow in the pseudo-locale `en-XA`).
