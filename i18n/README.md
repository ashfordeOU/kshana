# i18n catalogues

Project Fluent (`.ftl`) catalogues for the site, the docs, the Studio and the engine. English is the source and the fallback.
Design: kshana-pro `docs/design/i18n-0.40-design.md` (v2).

```
i18n/en/ui.ftl         site chrome, notices, switcher, Studio shell      (by hand)  ids site-*, notice-*, studio-*
i18n/en/glossary.ftl   terms: -tier-*, -verdict-*, -status-*, -term-*, -cmd-*, -unit-*, -advisory, -mt-notice   (by hand)
i18n/en/engine.ftl     text the engine writes for people                  ids engine-*
i18n/en/pages/*.ftl    one built page per file, generated by `extract`    ids seg-<sha12>
i18n/<lang>/...        the same file names, translated
```

## For translators

1. Copy the English file to `i18n/<lang>/` under the same name and translate the values. Keep every id, every
   `{ $variable }`, `{ -term }`, string-literal placeable (`{ "1,408" }`) and numbered tag (`<a1>..</a1>`, `<b>`, `<em>`,
   `<s1>`, `<c1/>`, `<br/>`). A `<cN/>` is a code span or a symbol kept verbatim; its text is in the comment above the message.
2. Numbers and versions are string-literal placeables so they cannot change; the build formats them for the locale.
3. A message with a count takes a selector for the plural categories of the language.
4. Never translate code, file names, commands, scenario and kind ids, or the tier and verdict words (see the glossary).

## Tools

`node tools/i18n.mjs extract [--src web] [--out i18n/en/pages]` regenerates `i18n/en/pages/` from the built English pages
(pages that no longer exist are removed). An unchanged English segment keeps its id; a changed one gets a new id.
Segments on 25 or more pages are written once to `pages/_shared.ftl`. `pages/_index.json` lists each page's segment ids.
The remaining commands (apply, check, status, pseudo, csslint) are being built.
