telecom-timing (scenario kind)

Scenario kind of the engine v0.40.0, family Clocks, timing and holdover. Advisory: analysis output from a research and engineering tool, not type-approved navigation equipment and not a safety-of-life service. Every label here is the engine's or the verification matrix's; a kind is MODELLED unless the matrix says otherwise (how a label is earned: the README's Evidence section).

What it does#

Telecom timing: time error, maximum time interval error (MTIE) and time deviation (TDEV) of a GNSS holdover, checked against ITU-T masks with a PASS or FAIL and a margin per mask. Input is either a SYNTHETIC HOLDOVER (an oscillator preset -- ocxo, rubidium, caesium or csac, each carrying the stability, aging and temperature figures of a named public Microchip datasheet -- plus the GNSS-loss time, record length and sample interval; the free-running clock carries white, flicker and, where the datasheet fit needs it, random-walk frequency noise, linear aging and a sinusoidal temperature term) or an INGESTED SERIES of [time_s, time_error_ns] pairs given inline (and, on native builds only, a CSV file). Masks: ITU-T G.8272 (07/2025) PRTC-A and PRTC-B (max|TE| 100 / 40 ns, MTIE Tables 1-2, TDEV Tables 3-4); G.8272.1 (2024) Amd. 1 (07/2025) ePRTC locked (30 ns, Tables 1-2) and ePRTC-A holdover (the Table 3 time-error envelope rising from 30 ns to 100 ns over the holdover period H set by the locked duration, MTIE Table 4, TDEV Table 5); G.8273.2 (2023) Amd. 2 (11/2025) T-BC/T-TSC classes A-C (max|TE|, constant time error, low-pass-filtered MTIE and TDEV) and class D (max|TE_L| 5 ns, the only class D figure not left for further study); G.8271.1 (2022) Amd. 3 (05/2025) reference point C (max|TE_L| 1100 / 600 / 100 ns with MTIE Tables 7-1 to 7-3). Every entry a Recommendation marks for further study is absent rather than filled in, and each report lists what is not implemented. Also reports the time to exceed each maximum-time-error budget (defaults: 100 ns ePRTC max|TE_HO|, 400 ns network holdover allocation, 1100 ns point C, 1.5 us class 4), the MTIE/TDEV curves as a CSV table with each mask limit, and a units-and-provenance entry per numeric field. VALIDATED: the MTIE and TDEV estimators against the allantools package on a committed holdover series. MODELLED: the mask tables are transcriptions, and a synthetic holdover is a model built from datasheet maxima, not a measurement of any unit. Not a conformance test.

One run of scenarios/telecom-synce-eec.toml summarises as: telecom-timing: max|TE| 488.2 ns over 12000 s; g8262-eec-option-1 FAIL, g8262-eec-option-2 FAIL, g8262-1-eeec FAIL (MODELLED)

Limitations#

What the run's own report says is not modelled or not validated:

  • every requirement the Recommendations mark 'for further study' (class D beyond max|TE_L|, ePRTC-B holdover, T-BC/T-TSC holdover with both inputs lost, TDEV network limits, ePRTC-A holdover MTIE and TDEV beyond 10 000 s) (result not_implemented[0])
  • high-pass-filtered dynamic time error (dTE_H, G.8273.2 Table 7-7 and G.8271.1 clauses 7.3.2-7.3.3) (result not_implemented[1])
  • the variable-temperature MTIE of G.8273.2 Table 7-6 and the physical-layer-assisted holdover MTIE of G.8273.2 Table 7-10 (result not_implemented[2])
  • relative time error (cTE_R, dTE_R,L) between two outputs (result not_implemented[3])
  • the moving-average packet filter G.8272 and G.8272.1 state for PTP interfaces: the series is treated as one pulse per second time interval error (result not_implemented[4])
  • MODELLED — time error, MTIE and TDEV checked against transcribed ITU-T masks. The estimators are validated against allantools; the mask tables are transcriptions of the named Recommendations; a synthetic holdover is a model built from public datasheet figures, not a measurement of any unit. Not a conformance test. (result label)
  • MODELLED: the mask tables are transcriptions, and a synthetic holdover is a model built from datasheet maxima, not a measurement of any unit. (kind catalogue (kshana kinds --json))
  • The clock: the OCXO preset (Microchip OX-208 datasheet, Rev 12-1-2021), free-running from the first sample with white, flicker and (where the fit needs it) random-walk frequency noise fitted to the datasheet's Allan-deviation maxima, and its linear aging. The temperature is held constant (amplitude 0 K), as the masks assume. (scenario file comment, lines 12 to 15)
