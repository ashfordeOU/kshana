# Pre-registration: multi-revolution Lambert (M >= 1) against pykep

Committed alone, before the engine's multi-revolution solver is compared with any reference
value. It fixes the case set, the quantities, the bars and the oracle. Bars may be tightened
later, never loosened; a miss is recorded with its numbers.

## What is compared

`maneuver::lambert_multirev(r1, r2, tof, mu, prograde, max_revs)` (new): every solution of
Lambert's problem with up to `max_revs = 3` complete revolutions, in the order
`[M = 0, (M = 1, left), (M = 1, right), (M = 2, left), ...]` (Izzo 2015, "Revisiting
Lambert's problem", Celestial Mechanics and Dynamical Astronomy 121). The `M = 0` entry is the
existing single-revolution `maneuver::lambert`, unchanged.

Quantities, per case:

1. the number of solutions, `1 + 2 * Nmax` with `Nmax <= 3`;
2. for every solution, the departure velocity `v1` and the arrival velocity `v2` (3-vectors).

## Oracle

pykep 3.0.1 (`lambert_problem`, the C++ kep3 core, MPL-2.0, https://github.com/esa/pykep),
installed from PyPI and run as a separate program by `scripts/gen_lambert_multirev_ref.py`,
which writes `tests/fixtures/lambert_multirev/reference.csv`. No pykep code is copied into
Kshana. pykep's `cw` flag is `!prograde`; its solution `2M - 1` is the left branch and `2M` the
right branch. (The 3.0.1 wheel's package `__init__` fails on a missing data file of an unrelated
module; the script loads the compiled `pykep.core` extension directly. The Lambert code is
unaffected.)

## Case set (deterministic, fixed now)

All cases are generated by the script from `random.Random(20261012)` in the order below.
Units: families A to C are canonical (`mu = 1`), family D is heliocentric SI.

- **A, random 3-D (300 cases).** For `i = 0..299`: `|r1| ~ U(0.5, 2.0)`, `|r2| ~ U(0.5, 3.0)`;
  each direction a normalised triple of `gauss(0, 1)` draws (r1 then r2); the draw is
  repeated (same stream) while the transfer angle is under 1 deg or over 179 deg;
  `tof = exp(U(ln 0.5, ln 60))`; prograde for even `i`, retrograde for odd `i`.
- **B, near 180 deg (18 cases).** `r1 = [1, 0, 0]`,
  `r2 = 1.5 [cos t, sin t cos 30deg, sin t sin 30deg]` for `t` in {179.0, 179.9, 179.99} deg,
  `tof` in {2, 10, 25}, prograde and retrograde.
- **C, near the minimum time of flight of the top revolution count (24 cases).** Four
  geometries `r1 = [1, 0, 0]`, `r2 = k [cos t, sin t, 0.1]` with `(k, t)` in
  {(1.0, 60 deg), (1.5, 120 deg), (2.0, 200 deg), (0.8, 300 deg)}; for `M` in {1, 2, 3}, the
  oracle's minimum time `T_min(M)` (bisection on pykep's `Nmax` with `multi_revs = M`, to a
  relative width of 1e-13), and `tof = T_min(M) (1 + d)` for `d` in {1e-2, 1e-3}; prograde.
- **D, heliocentric (40 cases).** `mu = 1.32712440018e20 m^3/s^2`, `au = 1.495978707e11 m`;
  `|r1|, |r2| ~ U(0.7, 1.7) au`; direction `(cos L, sin L, z)` normalised, `L ~ U(0, 2 pi)`,
  `z ~ U(-0.05, 0.05)` (r1 then r2), redrawn while the angle is under 1 deg or over 179 deg;
  `tof ~ U(30, 1500)` days; prograde for even index, retrograde for odd.

Every case is solved with `max_revs = 3`. For each solution of `M >= 1` the script also records
`d_M = tof / T_min(M) - 1` from the same bisection.

## Bars

- Solution count: equal to pykep's in every case (all families).
- Velocities: `|v1 - v1_pykep| / |v1_pykep| <= 1e-8` and `|v2 - v2_pykep| / |v2_pykep| <= 1e-8`
  for every solution, except a branch with `d_M < 1e-2` (within 1 % of its minimum time, where
  the left and right branches merge and the root is ill-conditioned): there the bar is `1e-6`.

The comparison is `tests/lambert_multirev_oracle.rs`. The test also checks, as an internal
consistency guard and not as evidence, that each multi-revolution `v1` propagated two-body by
`maneuver::kepler_universal` over `tof` lands on `r2`.

## Outcome rule

All bars met: the multi-revolution Lambert row is VALIDATED against pykep. Any miss is
recorded in `docs/design/evidence/lambert-multirev/RESULTS.md` with its numbers, the test is
kept asserting the honest outcome (or `#[ignore]`d with the numbers), and the row stays
MODELLED for what missed.
