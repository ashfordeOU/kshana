# BOC(1,1) ambiguity resolution (bump-jump) and BOC(1,1) DLL scaling: pre-registration

Written and committed **before** any of the measurements below was run (item CAP-07 (a)).
The bars are fixed here; they may be tightened after a run, never loosened. A miss is recorded
in `RESULTS.md` with its numbers as a finding and is not tuned away. Label: **MODELLED**
(internal consistency against injected truth and closed forms). No external receiver output is
compared: GNSS-SDR and PocketSDR are not run on these signals here.

## The change (opt-in; defaults unchanged)

`LoopConfig` gains `boc: Option<BocTracking>`, `None` by default. With `None` every existing
output is byte-identical (no new taps, no rescaling, no jumps). With `Some`:

1. **DLL scaling for sine BOC(1,1).** Near zero, the BOC(1,1) autocorrelation is
   `R(τ) = 1 − 3|τ|` (|τ| ≤ 0.5 chip), three times as steep as the BPSK triangle. The three
   DLL discriminators are rescaled so that they read the code error in chips with unit slope on
   that main peak: early-minus-late power and envelope by `(2 − 3d)/(3(2 − d))`, the dot product
   by `1/3`. The early-late spacing must lie in `(0, 2/3)` chip, so that E and L stay on the
   positive part of the main peak.
2. **Bump-jump** (very-early / very-late correlators at ±one subcarrier half-period, 0.5 chip
   for BOC(1,1), reusing the channel's extra-tap correlators). After each loop update, a VE
   counter goes up by one when `|VE| > |P|` and down by one (not below 0) otherwise; a VL
   counter likewise. When a counter reaches the threshold `N` the code NCO is jumped by one
   half-period towards that tap (early: +0.5 chip; late: −0.5 chip) and both counters reset.

## Test configuration (fixed now)

* Signal: BeiDou B1C **data** component, PRN 19 (`signals::beidou::b1c_data`, sine BOC(1,1),
  10 230 chips, 10 ms), seeded 10 ms data symbols (`NavData::Seeded`), generated by
  `iq::scene` on a range profile with Doppler +1250 Hz, thermal noise, seeded. Galileo E1
  memory codes are not used.
* Sampling: 5.0 MS/s complex (4.888 samples per chip, not commensurate).
* Loop: 1-period (10 ms) integration; early-minus-late power DLL, `d = 0.2` chip, first
  order, Bn = 1 Hz, carrier-aided; Costas (atan) PLL second order Bn = 10 Hz, FLL-assisted
  (first order, 5 Hz) during pull-in; default lock thresholds.
* Bump-jump: `N = 8`, offsets ±0.5 chip.
* Initial Doppler error +2 Hz. Code-phase error at start: stated per test.
* Code error: the replica's `code_phase_chips` at `sample_index` minus the scene truth code
  phase at that sample, wrapped to ±L/2.

## Bars

* **B1 (the problem, option off).** Starting the code NCO on a side peak, +0.5 chip and
  −0.5 chip from the truth, at 45 dB-Hz, for 3 s, with `boc = None` (BPSK scaling, no
  bump-jump): the mean code error over `2 s ≤ t < 3 s` has magnitude in [0.40, 0.70] chip with
  the sign of the start offset (stays false-locked; the side-peak false-lock point predicted for
  EMLP with `d = 0.2` is `±(0.5 + d/4) = ±0.55` chip).
* **B2 (the fix).** The same two starts with the option on (BOC(1,1) scaling + bump-jump,
  `N = 8`), at 45 dB-Hz and at 35 dB-Hz, 3 s each:
  * the first jump happens within **0.5 s** of the start and is towards the main peak (a
    start of +0.5 chip, the replica ahead, gives a −0.5 jump; a −0.5 start, a +0.5 jump);
  * exactly one jump in the run;
  * RMS code error over `2 s ≤ t < 3 s` at most **0.05 chip**.
* **B3 (false jumps on the IQ chain).** Option on, start on the main peak (code error 0), at
  35, 40 and 45 dB-Hz, 4 s each: **zero** jumps, and RMS code error over `2 s ≤ t < 4 s` at
  most 0.05 chip.
* **B4 (scaling on the sampled signal).** Noise-free B1C at 5 MS/s, replica offset by
  `ε ∈ {−0.06, −0.03, +0.03, +0.06}` chip, `d = 0.2`, EMLP: with the BOC(1,1) scaling the
  discriminator reads `ε` within 10 % (slope in [0.9, 1.1]); without it (BPSK scaling) it reads
  about `3(2 − d)/(2 − 3d) = 3.86 ε` (slope above 3.0). Also, as a unit test on the ideal
  `1 − 3|τ|` peak, all three discriminators with the BOC(1,1) scaling are within 10 % of `ε` for
  `d ∈ {0.1, 0.2, 0.5}` and `ε ∈ {−0.05, 0.02, 0.08}` with `|ε| + d/2 < 1/3`.
* **B5 (false-jump rate, long seeded run, correlator level).** The detector alone
  (`BumpJump`) fed seeded correlator triples `(VE, P, VL)` with the exact noise covariance of
  the BOC(1,1) autocorrelation (`R(0.5) = −0.5`, `R(1.0) = 0`) and the signal on the main peak
  (code error 0), `T = 10 ms`, 100 000 updates (1000 s) per C/N0:
  * at 30, 35, 40 and 45 dB-Hz: **zero** false jumps;
  * at 25 dB-Hz: at most **1** false jump (prediction ≈ 2e-3 expected jumps from the
    random-walk bound `(p/(1 − p))^N` with `p = Q(0.5·A/σ) ≈ 0.10`).
  * Detection on the same model, signal on the side peak (`+0.5` chip), 1000 trials of 50
    updates at 35 dB-Hz: at least 99 % jump within 50 updates, all towards the main peak.

The correlator-level model (B5) is what makes a 1000 s run affordable in the debug test
profile; B3 covers the same question on the full IQ chain over 12 s.
