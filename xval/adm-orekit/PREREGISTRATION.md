# Pre-registration: CCSDS Attitude Data Messages (AEM, APM) against Orekit 13.1.8

Committed alone, before the engine's attitude-message writer or reader is compared with the
oracle on any case. It fixes the oracle, the quantities, the case set, the bars, the decision
rule and what counts as a finding. Bars may be tightened after the run, never loosened.

## What is under test

A new module `src/adm.rs`: writer and reader for the CCSDS Attitude Data Messages of
CCSDS 504.0-B-2 (Blue Book, Issue 2, January 2024):

- **AEM** (Attitude Ephemeris Message), KVN (keyword = value notation) and NDM/XML. Version 2.0
  (scalar part `QC` last, direction always A to B, letter rotation sequences such as `ZYX`), and
  version 1.0 in KVN (the 504.0-B-1 keywords `ATTITUDE_DIR` = A2B/B2A, `QUATERNION_TYPE` =
  FIRST/LAST, numeric rotation sequences such as `321`). Header, metadata (object, frames A and
  B, time system, start/stop and useable start/stop times, attitude type, rotation sequence,
  angular-velocity frame, interpolation method and degree), several segments, comments.
- **APM** (Attitude Parameter Message) version 2.0, KVN and NDM/XML: header, metadata, epoch,
  and the quaternion (with optional derivative), Euler angle (with optional rates), angular
  velocity, spin (with nutation or momentum), inertia and maneuver blocks.
- Convention helpers: the A-to-B quaternion of a record of quaternion, Euler-angle or spin type
  (504.0-B-2 Annex F: F2 quaternion, F3 Euler angles, F5.2 spin attitude at epoch), and the
  mapping from the engine's attitude quaternion.

## Oracle

Orekit 13.1.8 with Hipparchus 4.0.3 (Apache-2.0; jars from Maven Central, toolchain recorded in
`xval/d8-orekit13/`), run as a separate Java program: `org.orekit.files.ccsds.ndm.ParserBuilder`
(`buildAemParser`, `buildApmParser`) and `org.orekit.files.ccsds.ndm.WriterBuilder`
(`buildAemWriter`, `buildApmWriter`), data directory holding only `tai-utc.dat`. The driver and
its output are committed beside the fixture; CI compares against the committed output.

## Legs and quantities

- **L1, the engine writes and Orekit reads.** For every case the engine writes the message
  (KVN; and XML for every version-2.0 case). Orekit must parse each file without error. The driver
  dumps, at full precision: header values (version, creation date, originator, message id,
  comment count), metadata values, and every data record. AEM records are dumped in the message's
  own convention by Orekit's own inverse mapping (`AttitudeType.generateData` with the parsed
  metadata's quaternion order, direction, rotation sequence and rate frame), converted from SI to
  the message units (deg, deg/s, s, 1/s). APM blocks are dumped from Orekit's parsed block
  objects (raw components). Compared with the case inputs.
- **L2, Orekit writes and the engine reads.** The driver builds every case from the same inputs
  (a plain-text input file written by the test) through Orekit's own objects
  (`AttitudeType.build`, `AemMetadata`, `ApmQuaternion`, `Euler`, `AngularVelocity`,
  `SpinStabilized`, `Inertia`, `Maneuver`) and writes it with `AemWriter` / `ApmWriter` (KVN for
  every case; XML for every version-2.0 case). The engine parses each file; the parsed values are
  compared with the case inputs.
- **L3, convention.** For every AEM record of quaternion, Euler-angle or spin type, the engine's
  A-to-B quaternion, expressed as Orekit's external-to-body rotation (the quaternion itself when
  frame A is the external frame, its conjugate when frame A is the spacecraft frame, and the
  direction flag of version 1.0 applied), equals the rotation Orekit built from the same record
  (`AemSegment.getAngularCoordinates()`), up to overall sign.
- **L4, schema (data-gated, not part of the verdict).** Every version-2.0 XML message the engine
  writes validates with `xmllint --schema` against the NDM/XML 4.0.0 master schema fetched at test
  time from the SANA registry (the schemas carry no redistribution licence, so they are not
  vendored; URL and SHA-256 recorded in the fixture NOTICE).

## Case set (fixed now)

Synthetic, deterministic inputs generated by the test (values written to the input file at full
precision). Epochs on whole or decimal seconds with at most 6 fractional digits. Time systems
UTC, TAI, GPS, TT and TDB. Frames EME2000, GCRF, LVLH, SC_BODY_1, SC_BODY_2, INSTRUMENT_A (frames
whose construction needs Earth orientation or planetary ephemerides are not used: the oracle
build has neither). Euler angles drawn inside the canonical branch the oracle's rotation
round trip returns (Tait-Bryan: first and third angle in (-180, 180) deg, second in (-90, 90)
deg; proper Euler: second in (0, 180) deg), so that L1 measures parsing, not angle wrapping.

AEM (14 cases, 5 records per segment):

APM (4 cases, version 2.0, at most one block of each kind except maneuvers):

| id | blocks |
|---|---|
| P01 | quaternion only, header comments, MESSAGE_ID |
| P02 | quaternion with derivative, Euler angles with rates, angular velocity, inertia, two maneuvers (one with MAN_DELTA_MASS) |
| P03 | Euler angles (proper ZXZ, no rates), spin with NUTATION / NUTATION_PER / NUTATION_PHASE |
| P04 | quaternion, spin with MOMENTUM_ALPHA / MOMENTUM_DELTA / NUTATION_VEL, inertia |

Exclusions stated now: AEM version 1.0 `QUATERNION/RATE` and `EULER_ANGLE/RATE`, and XML for
version 1.0, are outside the case set (the engine reads and writes them; MODELLED only).
504.0-B-2 lets an APM repeat any block (3.2.4.4); Orekit 13.1.8 keeps one block of each kind
except maneuvers, so repeated blocks are covered by the engine's own round trip only (MODELLED).

## Bars

Header, metadata and frame strings: identical (Orekit's normalised spelling of a frame name is
compared by name). Epochs: equal within 1e-9 s (both sides parse the same decimal).

| quantity | bar |
|---|---|
| quaternion components (Q1, Q2, Q3, QC) | abs 1e-14 |
| quaternion derivatives | abs 1e-14 1/s |
| Euler angles, spin alpha/delta/angle, momentum alpha/delta (L1, L2) | abs 1e-9 deg; spin and momentum angles compared modulo 360 deg |
| angle rates, angular velocities, spin angle velocity, nutation velocity | abs 1e-10 deg/s |
| SPIN/NUTATION and SPIN/NUTATION_MOM records (L1, L2; Orekit rebuilds them through its own spin and precession finders) | angles abs 1e-8 deg (modulo 360), rates abs 1e-9 deg/s, nutation period rel 1e-10 |
| APM raw values (quaternion, angles, rates, inertia, torques, duration, delta mass) | rel 1e-14 (abs 1e-14 for values below 1) |
| L3 rotation, every quaternion, Euler and spin record | max abs component difference 1e-12, up to overall sign |

## Decision rule

- **Validated** (the attitude-message interchange, AEM and APM, KVN and XML, against Orekit): every
  case parses in both directions and every bar of L1, L2 and L3 holds.
- **Finding:** any parse failure, any value outside its bar, any metadata string that differs,
  or any rejection by Orekit of a message the standard allows. Each is reported with the case,
  the field and both values, and kept as a pinned finding in the test; the bars above are not
  edited to fit it. A finding confined to one attitude type or version narrows the claim to the
  types that pass; it is not tuned away.
- Convention gaps between 504.0-B-1 and 504.0-B-2 (for example `QUATERNION_TYPE` and
  `ATTITUDE_DIR`, removed in version 2.0) and between the standard and Orekit are recorded as
  findings in the test's module documentation whether or not a bar fails.
