# Pre-registration: CCSDS Orbit Data Messages (OPM, OMM, OCM) against Orekit 13.1.8

Committed alone, before the engine's orbit-message writer or reader is compared with the oracle
on any case. It fixes the oracle, the quantities, the case set, the bars, the decision rule and
what counts as a finding. Bars may be tightened after the run, never loosened.

## What is under test

A new module `src/odm.rs`: writer and reader for three of the Orbit Data Messages of
CCSDS 502.0-B-3 (Blue Book, Issue 3, April 2023), KVN (keyword = value notation) and NDM/XML:

- **OPM** (Orbit Parameter Message), versions 3.0 and 2.0: header (comments, classification,
  creation date, originator, message id), metadata (object name and id, centre, reference frame,
  time system), state vector, osculating Keplerian elements (true or mean anomaly, GM),
  spacecraft parameters, position/velocity covariance (with its own frame), maneuvers
  (repeatable) and user-defined parameters.
- **OMM** (Orbit Mean-Elements Message), versions 3.0 and 2.0: header, metadata (including
  `MEAN_ELEMENT_THEORY`), mean elements (mean motion or semi-major axis), spacecraft parameters,
  TLE-related parameters (`EPHEMERIS_TYPE`, `CLASSIFICATION_TYPE`, `NORAD_CAT_ID`,
  `ELEMENT_SET_NO`, `REV_AT_EPOCH`, `BSTAR` or `BTERM`, `MEAN_MOTION_DOT`, `MEAN_MOTION_DDOT` or
  `AGOM`), covariance and user-defined parameters. A full-precision writer is added beside the
  existing `OmmFile::to_omm_kvn`, whose output stays byte-identical.
- **OCM** (Orbit Comprehensive Message), version 3.0, scoped to: header; metadata (identification,
  time system, `EPOCH_TZERO` and the other keywords the case set uses); trajectory blocks
  (`TRAJ_START`..`TRAJ_STOP`) of the Cartesian types `CARTP`, `CARTPV`, `CARTPVA`, with absolute
  or relative (seconds from `EPOCH_TZERO`) record epochs; physical-properties block (`PHYS`);
  covariance blocks (`COV`) of types `CARTP` and `CARTPV` in `LTM` ordering; maneuver blocks
  (`MAN`) with the compositions of the case set; user-defined block (`USER`). **Out of scope,
  stated now**: perturbations (`PERT`) and orbit-determination (`OD`) blocks, non-Cartesian
  trajectory and covariance element sets, covariance orderings other than `LTM`, and maneuver
  fields outside the case set. The engine keeps unknown metadata and physical-properties keywords
  verbatim but they are not claimed.

## Oracle

Orekit 13.1.8 with Hipparchus 4.0.3 (Apache-2.0; toolchain `xval/d8-orekit13/`), run as a
separate Java program `xval/odm-orekit/OdmOracle.java`: `ParserBuilder` (`buildOpmParser`,
`buildOmmParser`, `buildOcmParser`) and `WriterBuilder` (`buildOpmWriter`, `buildOmmWriter`,
`buildOcmWriter`), data directory holding only `tai-utc.dat` (plus whatever stub the harness
needs to resolve `CENTER_NAME = EARTH` by name, as in the ADM driver; recorded in the driver's
header if used). The driver and its outputs are committed beside the fixture; CI compares
against the committed outputs.

## Legs and quantities

- **L1, the engine writes and Orekit reads.** For every case the engine writes the message in
  KVN and in XML (XML for version-3.0 cases only). Orekit must parse each file without error.
  The driver dumps, at full precision and in the message units (km, km/s, km/s², deg, km³/s²,
  kg, m², 1/day, 1/day², 1/day³, km², km²/s, km²/s², m/s, s), every header, metadata and data
  value it parsed, read from Orekit's parsed objects. Compared with the case inputs.
- **L2, Orekit writes and the engine reads.** The driver writes every message Orekit parsed in
  L1 back out with Orekit's own writer (KVN from the KVN file, XML from the XML file). The engine
  parses each Orekit-written file; the parsed values are compared with the case inputs.
- **L3, schema (data-gated, not part of the verdict).** Every XML message the engine writes
  validates with `xmllint --schema` against the NDM/XML 4.0.0 master schema fetched at test time
  by `xval/ndm-xsd/validate.sh` (SHA-256 pinned there).
- **Legacy writer (recorded, not part of the verdict).** The KVN of the existing
  `OmmFile::to_omm_kvn` for one TLE-derived case is given to Orekit's OMM parser; whether it
  parses, and what it reads, is recorded as is.

## Case set (fixed now)

Synthetic, deterministic inputs generated by the test (values written at full precision).
Epochs on whole or decimal seconds with at most 6 fractional digits. Time systems UTC, TAI, GPS,
TT, TDB. Centre `EARTH` only. Frames EME2000, GCRF and TEME (OMM), and the local orbital frames
RTN and TNW for covariance and maneuvers. Frames needing Earth orientation data beyond what the
oracle build can construct are not used; if Orekit cannot construct TEME without Earth orientation
parameters, that is recorded as a harness limitation and the TEME cases are judged on the
values Orekit reads, not on frame transforms (none is computed).

## Bars

Header, metadata, frame and keyword strings: identical (Orekit's normalised spelling of a frame
name is compared by name). Epochs: equal within 1e-9 s (both sides parse the same decimal).
Integers (catalogue number, element set number, revolution number): exact.

| quantity | bar |
|---|---|
| every real value (state, elements, GM, spacecraft and physical properties, TLE parameters, covariance terms, maneuver values, relative epochs) | relative 1e-14 of the larger magnitude; exact for zero |
| user-defined parameter values | identical strings |

## Decision rule

- **Validated** (orbit-message interchange with Orekit, per message type and per notation): every
  case of that type parses in both directions and every bar of L1 and L2 holds.
- **Finding:** any parse failure, any value outside its bar, any string that differs, or any
  rejection by Orekit of a message the standard allows. Each is reported with the case, the field
  and both values, and kept as a pinned finding in the test; the bars are not edited to fit it. A
  finding confined to one message type, version or block narrows the claim to what passes.
- Gaps between 502.0-B-2 and 502.0-B-3 and between the standard and Orekit are recorded in the
  test's module documentation whether or not a bar fails.
