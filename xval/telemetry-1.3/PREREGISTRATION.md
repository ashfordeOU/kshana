# Pre-registration: telemetry schema 1.3 stream through four independent consumers

Committed alone, before any schema-1.3 output of the engine is given to any of the oracles
below. Bars may be tightened after the run, never loosened.

## What is under test

The schema-1.3 additions of the trust telemetry (`src/telemetry/`): the satellite-geometry
series (Prometheus `kshana_trust_geometry`, `_degraded`, `_signal_loss`, `_hdop`, `_pdop`,
`_used_satellites`, `_epochs_total`, `_label`, `_vdop`; OTLP `kshana.geometry.status`,
`.degraded`, `.signal_loss`, `.hdop`, `.pdop`, `.used_satellites`, `.label`, `.vdop`) and the
`class` label on `kshana_trust_reason_active`, together with every 0.35 series, rendered for a
schema-1.3 stream. Today's telemetry oracle (`tests/telemetry_formats_reference.rs`) covers a
schema-1.2 stream only and states that promtool and a real collector were not run.

## Corpus (fixed now)

`tests/fixtures/telemetry_oracle_13/stream.jsonl`, synthetic and deterministic, generated by the
test: at least 60 lines mixing schema-1.2 lines (no `geometry`) and schema-1.3 lines whose
`geometry` covers the statuses `good`, `degraded`, `unknown` and an unknown status string; HDOP,
PDOP, used-satellite count and VDOP present, null or absent; labels `good`, `fair`, `poor`,
`unknown` and an unknown label string; `signal_loss` true, false, null and absent; deductions
with `class` `inconsistency`, `environment`, `geometry` and an unknown class; reason names with
quotes, backslashes, line feeds and non-ASCII text; positions; gate states; and a few lines that
do not parse. The last parsable line carries geometry with every field, so every geometry
series is rendered. The registry is fed as `tests/telemetry_formats_reference.rs` feeds it
(fixed clock `NOW`, OTLP stamp `NOW_NANO`, position exposed). The engine's outputs
`exposition.prom` and `otlp.json` are committed and must equal what the crate produces.

## Oracles

1. **prometheus_client 0.26.0** `parser.text_string_to_metric_families` (the existing oracle).
2. **opentelemetry-proto 1.45.1** `ExportMetricsServiceRequest` through protobuf 7.36.2
   `json_format.Parse(ignore_unknown_fields=False)` (the existing oracle).
3. **promtool** `check metrics` from the Prometheus 3.5.0 release
   (`prometheus-3.5.0.linux-amd64.tar.gz`, SHA-256
   `e811827af26d822afb09a4f28314f61b618b12cff5369835a67f674d8b46f39a`, equal to the release's
   `sha256sums.txt`), fed `exposition.prom` on standard input.
4. **OpenTelemetry Collector contrib 0.135.0** (`otelcol-contrib_0.135.0_linux_amd64.tar.gz`,
   SHA-256 `43132748eb0effb56b9d508ca789149684bf7ab6ade5d65cd0b22c4d265a30c0`, equal to the
   release's checksums file), with an `otlp` receiver (HTTP) and a `file` exporter (JSON) and no
   processor; `otlp.json` is POSTed to `/v1/metrics` as `application/json`.

The tools are fetched at run time by `xval/telemetry-1.3/run.sh` and checked against the digests
above (a mismatch fails). Their outputs are committed (`prometheus_reference.json`,
`otlp_reference.json`, `promtool.txt`, `collector_export.json`); the test compares the committed
outputs, so CI needs none of the tools. Data-gated: the run needs network access to the two
release downloads.

## Bars

- **O1, prometheus_client**: as pre-registered in `tests/telemetry_formats_reference.rs`, applied
  to the 1.3 corpus: the set of families, each family's name, type and help, and the set of
  samples (name, label set, value) equal those the registry implies, exactly (values by `f64`
  equality), no extra or missing family or sample; the registry-implied set now includes the
  geometry families and the `class` label.
- **O2, OTLP proto**: as pre-registered there, exactly, including the geometry metrics.
- **O3, promtool**: exit status 0 and no output (no parse error and no lint problem). Any lint
  problem is a finding, recorded verbatim; it is not removed by editing the bar.
- **O4, Collector**: HTTP status 200 with a response the receiver accepts (no partial-success
  rejection), and the file exporter's record of the request, read with the same normalisation as
  O2, equals the O2 reading of `otlp.json` exactly (resource attributes, scope name, every
  metric's name, description, unit, kind, monotonicity, temporality, and every point's
  attributes, value, value kind, start time and time), with no extra or missing metric or point.

## Decision rule

The 1.3 telemetry row is VALIDATED for these four consumers only if every bar holds. A bar that
fails is a finding, kept as a test that asserts the recorded miss; the claim narrows to the
consumers that pass. Not covered, stated now: delivery, retries and timeouts of the live
exporter; the Collector reading the Prometheus exposition (its `prometheus` receiver); the
semantic fitness of the metrics for any dashboard; CEF and LEEF.
